TL;DR — We recast complete autonomy in a coding-agent harness as ergodicity of its state dynamics. The payoff is three concrete, CI-auditable numbers: a polynomial mixing-time bound \(t_{\text{mix}} = O(N^2/\delta)\) that tells you the worst-case ticks to full task coverage; a KAM perturbation threshold \(\varepsilon_{\max}\) bounding how many constraints you can add before autonomy breaks; and a linear program whose solution is the maximal-autonomy invariant measure. If you are building a ReAct-style or plan-act harness, these three numbers are the ones to compute before your next release.

Abstract

We model the coding-agent harness as a measure-preserving transformation \(T\) on a finite state space \(\Omega\) of \(N\) discrete harness configurations (tool selections, context windows, permission states, and loop phases). We define complete autonomy as the ergodicity of \(T\): the irreducibility of the dynamics into a single invariant component, so that no proper subset of states is closed under the dynamics. Under this definition, we prove a polynomial mixing-time bound of the form \(t_{\text{mix}} \leq C\, N^2 / \delta\), where \(\delta\) is the spectral gap of the associated transition matrix and \(C\) is a universal constant. We then apply Kolmogorov–Arnold–Moser (KAM) perturbation theory to show that additive constraint perturbations of magnitude \(\varepsilon < \varepsilon_{\max}(\delta, N)\) preserve the ergodic structure, yielding a certifiable robustness margin. Finally, we formulate an ergodic-optimization linear program whose solution identifies the invariant measure \(\mu^*\) maximizing an autonomy objective (task-coverage entropy). Together, these results convert the qualitative question “is my agent autonomous?” into three quantitative, CI-auditable checks.

Why this matters. Let’s be honest about where harness evaluation stands right now. We’ve got benchmark scores everywhere—SWE-bench pass@k, AgentBench success rates, τ-bench trajectory fidelity—and they all measure outcome autonomy. Did the agent finish the task? Nice. But none of them bound the process autonomy: the guarantee that the agent will, within a computable number of steps, actually explore every relevant configuration rather than silently collapsing into some degenerate attractor it found early on. The ergodicity framework fills exactly that gap. It hands you a structural certificate, not a behavioral statistic. And that’s a fundamentally different thing to have in your CI pipeline.

Prerequisites

You’ll want some familiarity with finite-state Markov chains (transition matrices, stationary distributions, spectral decomposition), basic measure-preserving dynamics (ergodicity, invariant sets), and the ReAct / plan-act harness loop. No knowledge of symplectic geometry or KAM theory is required—we state only the corollary we use, and I’ll explain it in plain terms.

1. Why Ergodicity Is the Right Invariant for Agent Autonomy

1.1 The state space

A coding-agent harness at any given moment is characterized by a tuple

\[ s = (c,\; \tau,\; \pi,\; \phi) \in \Omega, \]

where \(c\) is the active context window (or a hash thereof), \(\tau\) is the selected tool or action, \(\pi\) is the permission/authorization state, and \(\phi\) is the loop phase (plan, act, observe, reflect). In a well-factored harness, \(\Omega\) is finite: \(|\Omega| = N\) for some \(N\) in the range \(10^1\)–\(10^4\) depending on tool count and phase granularity.

The harness transition \(T: \Omega \to \Omega\) is the deterministic (or stochastic, if the LLM sampling introduces entropy) map that takes the current configuration to the next. In the deterministic case, \(T\) is just a permutation of \(\Omega\); in the stochastic case, we work with the associated Markov kernel \(P(s, s') = \Pr[T(s') \mid s]\).

1.2 Defining autonomy as ergodicity

Definition 1 (Complete Autonomy). A harness \(T\) with state space \((\Omega, \mathcal{F}, \mu)\) is fully autonomous if and only if \(T\) is ergodic with respect to the uniform measure \(\mu\): for every measurable set \(A \subseteq \Omega\) satisfying \(T^{-1}(A) = A\) (i.e., \(A\) is invariant), either \(\mu(A) = 0\) or \(\mu(A) = 1\).

In plain language: there is no non-trivial “cage” of states the agent can get trapped in. The agent’s dynamics don’t fragment into disconnected behavioral modes. If \(T\) has two disjoint invariant sets \(A\) and \(B\), the agent is not autonomous—it has silently chosen a personality (always uses tool X, never enters the reflect phase, etc.) and will never, ever leave it. You’d never know unless you checked.

And here’s the thing: this definition is deliberately stronger than “the agent completes the task.” A task-completing agent might pass through only 5 of 120 states, ignoring the rest entirely. Ergodicity demands that all states are reachable in the long run. That’s the structural guarantee you actually want before you pull the human out of the loop.

1.3 Relation to prior work in the series

The five-level autonomy spectrum in The Autonomy Imperative gives us the qualitative ladder; ergodicity gives the top rung a rigorous predicate. The spectral-gap analysis in The Spectral Gap of Autonomy computes the convergence speed \(\delta\) that shows up as a parameter in our mixing bound. The percolation threshold in Percolation of Autonomy identifies the constraint density at which the invariant set fragments—precisely the point where ergodicity is lost. Our KAM certificate (§3) is the local-robustness companion to that global percolation picture.

2. Polynomial Mixing-Time Bound: A Quantitative Latency Certificate

2.1 The theorem

Let \(P\) be the \(N \times N\) stochastic transition matrix of the harness, with eigenvalues \(\lambda_1 = 1, \lambda_2, \dots, \lambda_N\). Define the spectral gap

\[ \delta \;=\; 1 - \max_{i \geq 2} |\lambda_i|. \]

Theorem 2 (Mixing-Time Bound). If \(P\) is aperiodic and irreducible, then the \(\varepsilon\)-mixing time satisfies

\[ t_{\text{mix}}(\varepsilon) \;\leq\; \frac{1}{\delta}\,\ln\!\frac{1}{\varepsilon\, \pi_{\min}}, \]

where \(\pi_{\min} = \min_s \pi(s)\) is the smallest stationary probability. In particular, for \(\varepsilon = 1/N\) (uniform accuracy) and \(\pi_{\min} \geq 1/N\),

\[ \boxed{\;t_{\text{mix}} \;\leq\; \frac{N}{\delta}\,\ln N\; = \; O\!\left(\frac{N^2}{\delta}\right).} \]

Sketch. The bound follows by decomposing \(P^t - \pi\mathbf{1}^T\) into its spectral components. The dominant non-trivial term decays as \(|\lambda_2|^t = e^{-\delta t}\) (up to sub-exponential factors from Jordan blocks, which are bounded by a polynomial in \(N\) for stochastic matrices via Weyl’s inequality applied to the symmetric part of \(P\)). Setting \(|\lambda_2|^t \leq \varepsilon\,\pi_{\min}\) and solving for \(t\) gives the stated bound. The \(N^2\) dependence arises from the worst-case \(\pi_{\min} = 1/N\) and the \(\ln N\) factor.

2.2 What this means for your harness

Okay, so now you actually have a CI-auditable latency guarantee. Before you ship a harness configuration, you can compute \(N\) (count your states), estimate \(\delta\) (run the spectral-conditioning algorithm from The Spectral Gap of Autonomy), and get a concrete upper bound on the number of ticks the agent needs before its behavior is statistically indistinguishable from the invariant measure.

Here’s the part that should get your attention: if \(t_{\text{mix}}\) exceeds your SLA (say, 10 000 tokens), you know a priori that the harness is structurally too slow. Not because the LLM is slow. Because the state space is poorly connected. That’s a design problem, not a model problem, and it means you can fix it without swapping models.

2.3 Worked example: a 12-state ReAct harness

Consider a harness with \(N = 12\) states: 4 phases (plan, act, observe, reflect) × 3 tool tiers (local, sandboxed, production). The transition matrix \(P\) is built from the ReAct loop: from any act state, the agent moves to observe; from observe, it probabilistically routes to plan (with probability 0.7) or reflect (0.3); from plan, it routes to act (1.0); from reflect, it routes to plan (0.8) or terminates (0.2, which we treat as a self-loop on the plan state for ergodicity purposes).

Suppose a numerical eigendecomposition yields \(\lambda_2 = 0.95\), so \(\delta = 0.05\). Then:

\[ t_{\text{mix}} \;\leq\; \frac{12}{0.05}\,\ln 12 \;\approx\; 240 \times 2.485 \;\approx\; 596 \text{ ticks}. \]

If your harness runs at 50 tokens/tick, that’s a 29 800-token worst-case exploration budget. Now, if your task SLA is 20 000 tokens, you’ve got a problem. The harness is structurally too slow at \(\delta = 0.05\). You need to either reduce \(N\) (merge tool tiers) or increase \(\delta\) (add more cross-phase transitions). Either way, you know before you hit production.

3. KAM Perturbation Certificate: How Much Constraint Can You Add?

3.1 The problem

In practice, nobody designs a harness in one shot. You start with a permissive core and incrementally bolt on constraints: a security policy that blocks rm -rf, a UI constraint that forces the agent to render diffs before committing, a spec checklist that gates the reflect phase. Each addition is a perturbation \(\Delta P\) to the transition matrix: \(P' = P + \Delta P\).

The question that keeps me up at night: how large can \(\|\Delta P\|\) be before ergodicity is destroyed?

3.2 The KAM certificate

The full KAM theorem (Kolmogorov, 1954; Arnold, 1963; Moser, 1962) concerns near-integrable Hamiltonian systems and is, frankly, overkill here. We use only the following corollary, which is a direct consequence of the implicit-function theorem applied to the eigenvalue equation:

Theorem 3 (Ergodicity Preservation under Perturbation). Let \(P\) be an \(N \times N\) irreducible, aperiodic stochastic matrix with spectral gap \(\delta > 0\). Let \(P' = P + \Delta\) where \(\Delta\) is a perturbation preserving row-stochasticity. If

\[ \|\Delta\|_{\infty} \;<\; \varepsilon_{\max} \;=\; \frac{\delta}{2\,(N-1)}, \]

then \(P'\) is also irreducible and aperiodic, and its spectral gap satisfies \(\delta' \geq \delta - 2N\|\Delta\|_{\infty}\).

Intuition (the “moat” picture). Think of the eigenvalue \(\lambda_1 = 1\) as an island and the remaining eigenvalues as points scattered in the complex plane. The spectral gap \(\delta\) is the width of the “moat” separating the island from the nearest point. A perturbation of magnitude \(\varepsilon\) shifts each eigenvalue by at most \(N\varepsilon\) (Gershgorin). If \(N\varepsilon < \delta/2\), no eigenvalue can cross the moat; the island stays isolated; irreducibility is preserved. In short: the gap is a moat, and a perturbation smaller than the moat width cannot bridge it.

3.3 Practical KAM budget

For the 12-state example above (\(\delta = 0.05\), \(N = 12\)):

\[ \varepsilon_{\max} = \frac{0.05}{2 \times 11} \approx 0.00227. \]

This means: each row of \(\Delta P\) can have \(L^1\) mass at most \(\approx 0.23\%\) redistributed. Concretely? If you add a security gate that diverts 5% of act/prod transitions to a blocked state, you are exceeding the KAM threshold by more than 20×. Ergodicity is not guaranteed; the agent may now be trapped in the blocked attractor. You added one safety check and broke the whole system.

What this means for your harness. Before adding any constraint, compute \(\varepsilon_{\max}\) from your current \(\delta\) and \(N\). If the constraint’s transition-mass shift exceeds \(\varepsilon_{\max}\), you’ve got three options: (a) reduce the constraint’s strength, (b) add compensating transitions to restore the gap, or (c) accept the loss of ergodicity and redesign the state space. This is a certifiable, per-constraint budget check that can run in a CI pipeline in \(O(N^3)\) time (one eigendecomposition). Five minutes of compute. Worth it.

3.4 The aperiodicity trade-off

The theorems above require aperiodicity (\(\gcd\) of return-time periods = 1). In practice, a ReAct loop with fixed phase ordering (plan → act → observe → plan) is periodic with period 3. A common fix is to add a small stochastic “skip” (e.g., 5% probability of staying in the same phase).

Does this break task-completion guarantees? No. But it does increase \(t_{\text{mix}}\) by a factor of at most \((1-\alpha)^{-1}\) where \(\alpha\) is the skip probability. At \(\alpha = 0.05\), the overhead is ≈ 6%. The structural benefit (aperiodicity, hence applicability of the mixing bound) far outweighs a 6% latency cost. Honestly, this is the single cheapest ergodicity fix available. Add the skip, move on.

4. Ergodic Optimization: Finding the Maximal-Autonomy Measure

4.1 The problem

Given a harness \(P\) that is ergodic, there’s a unique stationary distribution \(\pi\). But here’s where it gets interesting: you may have design freedom. The transition probabilities within each phase are not fixed by the LLM—they’re set by your harness code (routing rules, tool-selection heuristics, context-window management). So the question becomes:

Among all stochastic matrices \(P\) consistent with your architectural constraints (e.g., phase ordering, security gates), which \(P\) maximizes an autonomy objective?

A natural objective is the task-coverage entropy:

\[ \mathcal{H}(\pi) = -\sum_{s \in \Omega} \pi(s) \log \pi(s). \]

Maximizing \(\mathcal{H}(\pi)\) pushes the stationary distribution toward uniformity, which is the ergodic “ideal”: the agent spends equal long-run time in every configuration. No state is starved.

4.2 The linear program

The entropy-maximization is nonlinear, but the constraint set is linear, and the objective is concave, so the problem is a convex program. For a blog-level implementation, the LP relaxation (linearizing the entropy via its tangent at the uniform distribution) is sufficient and gives the same optimal vertex:

\[ \begin{aligned} \text{maximize} \quad & \sum_s \pi(s) \quad \text{(subject to } \pi \geq 0,\; \mathbf{1}^T\pi = 1) \\ \text{subject to} \quad & \pi P = \pi \\ & P \geq 0, \quad \mathbf{1}^T P = \mathbf{1} \quad \text{(row-stochastic)} \\ & P_{ij} \leq \bar{p}_{ij} \quad \text{(architectural upper bounds)} \\ & P_{ij} \geq \underline{p}_{ij} \quad \text{(security lower bounds)} \end{aligned} \]

4.3 A 5-line Python sketch

import numpy as np
from scipy.optimize import linprog

N = 5  # toy state space
# c: objective (maximize uniformity → minimize -sum π)
c = np.ones(N)
# A_eq: π P = π  →  (P^T - I) π = 0, plus sum(π) = 1
P = np.full((N, N), 1/N)  # start from uniform (feasible)
A_eq = np.vstack([np.hstack([P.T - np.eye(N), np.zeros(N)]),
                  np.ones(2 * N)])
b_eq = np.concatenate([np.zeros(N), [1.0]])
res = linprog(c, A_eq=A_eq, b_eq=b_eq, bounds=[(0, 1)] * N)
print("Optimal π:", res.x)

This is a toy, obviously. The production version replaces the fixed \(P\) with decision variables and adds the architectural bounds \(\bar{p}_{ij}\), \(\underline{p}_{ij}\). The solver (HiGHS, Gurobi, or even cvxpy) returns the maximal-autonomy stationary distribution in milliseconds for \(N \leq 10^4\). You’ll barely notice it running.

4.4 Relation to the free-energy bound

The ergodic LP is the constrained version of the variational free-energy bound developed in Free Energy Bounds: A Variational Account of Autonomy. Over there, the KL budget per step is the dual variable; here, the architectural bounds \(\bar{p}_{ij}\) play the same role. The two formulations are Fenchel-dual: the LP is the primal (choose transitions), the free-energy bound is the dual (pay a KL cost for deviation from the prior). For practitioners, I’d say the LP is the more actionable object. You can actually run it.

5. Common Harness Design Pitfalls (and How to Fix Them)

The following mistakes show up repeatedly in production harnesses, and they’re all diagnosable by the three numbers above (\(N\), \(\delta\), \(\varepsilon_{\max}\)):

# Pitfall Symptom Diagnostic Fix
1 Phase lock. The agent always cycles plan→act→observe and never enters reflect. \(\delta\) is small; a 3-state cycle is an invariant set. Check \(\gcd\) of return times; verify aperiodicity. Add a 5% stochastic skip (§3.4).
2 Tool-tier collapse. The agent selects the local tier 98% of the time, ignoring sandbox and production. \(\pi_{\min} \approx 0.005\); mixing time explodes. Compute \(\pi\); check entropy \(\mathcal{H}(\pi)\). Add a context-dependent routing rule that forces tier escalation on specific error patterns.
3 Security over-constraint. A new rm -rf block creates a blocked state with no outgoing edge. \(P\) loses irreducibility; \(\delta \to 0\). Run the KAM check: \(\|\Delta P\|_\infty > \varepsilon_{\max}\). Add a “retry with confirmation” transition out of the blocked state.
4 Context-window starvation. The context hash \(c\) has \(10^6\) possible values, making \(N\) enormous. \(t_{\text{mix}}\) is infeasible. Coarse-grain \(c\) (see Coarse-Graining Autonomy). Reduce \(N\) via RG flow; keep only the top-\(k\) context buckets.
5 Silent attractor. A rare error path (e.g., a 429 rate-limit) sends the agent into a retry loop that never exits. A 2-state invariant subset exists. Ergodicity test: find \(A \subset \Omega\) with \(P(A, A) = 1\). Add a max-retry counter that forces transition to reflect.

Each row is a 5-minute CI check: compute \(N\), run the eigendecomposition, verify \(\delta > 0\) and \(\|\Delta P\|_\infty < \varepsilon_{\max}\). If any check fails, the harness is not structurally autonomous. And I mean that no matter how well it scores on SWE-bench. A 95th-percentile benchmark score means nothing if the agent is stuck in a 3-state loop.

6. Positioning: How This Relates to SWE-bench, AgentBench, and τ-bench

The dominant agent-evaluation frameworks measure behavioral autonomy:

  • SWE-bench (Jimenez et al., 2023): pass@k on real GitHub issues. Measures outcome success.
  • AgentBench (Liu et al., 2023): multi-task success across web, OS, DB environments. Measures task coverage.
  • τ-bench (Yao et al., 2024): trajectory-level fidelity to a reference policy. Measures process similarity.

None of them answer the structural question: “Is the agent’s state dynamics ergodic? Will it, in the long run, explore all of its configuration space, or is it silently stuck in a subset?” A SWE-bench pass@1 of 30% is perfectly compatible with an agent that only uses 3 of its 12 states. You’d never know from the benchmark. The ergodicity certificate is orthogonal to these benchmarks: it’s a necessary (not sufficient) condition for genuine autonomy. I’d recommend running the ergodicity check as a pre-gate in the CI pipeline, before the benchmark suite is even invoked.

The rate-distortion cost floor in The Autonomy Channel gives you the information-theoretic lower bound on the distortion a harness must accept; the ergodicity bound gives you the temporal upper bound on how long convergence takes. Together, they bracket the design space: you cannot simultaneously minimize distortion and minimize mixing time below the product of the two lower bounds. That’s a hard wall.

7. How to Build \(P\) from Your ReAct Loop (Practical Guide)

The theorems assume you have the transition matrix \(P\). In practice, you have to extract it from harness code. Three steps:

  1. Enumerate states. Walk your harness source. Each distinct combination of (phase, tool-tier, permission-level) is one state. For a typical ReAct harness with 4 phases, 3 tool tiers, and 2 permission levels, \(N = 24\). Write this as a constant in your config: HARNESS_N = 24.

  2. Extract transitions. For each state \(s\), trace the control flow to identify the next state \(s'\) and the probability (if stochastic) or the deterministic target. In a plan-act harness, this is usually a hardcoded routing table. Encode it as an \(N \times N\) matrix. If the LLM sampling introduces stochasticity, estimate \(P_{ij}\) from a 1 000-episode trace.

  3. Validate. Check row-stochasticity (\(\sum_j P_{ij} = 1\) for all \(i\)), verify irreducibility (all states reachable), and compute \(\delta\) via numpy.linalg.eigvals(P.T). If \(\delta \approx 0\), you have an invariant subset—go back to step 2 and figure out where the disconnect is.

This is the same procedure as the spectral-conditioning algorithm in The Spectral Gap of Autonomy, extended with the KAM check and the ergodic LP.

9. Next Steps: Three Numbers to Compute Before Your Next Release

If you’re building a coding-agent harness and want a CI-auditable autonomy certificate, here are the three numbers to compute. Seriously, just these three:

  1. \(N\) — the state-space cardinality. Count your (phase, tool, permission) tuples. Target: \(N \leq 100\) (beyond that, coarse-grain via RG flow).

  2. \(\delta\) — the spectral gap. Run np.linalg.eigvals(P.T); take \(1 - \max|\lambda_i|\) for \(i \geq 2\). Target: \(\delta \geq 0.05\) (gives \(t_{\text{mix}} \leq 200\,N\ln N\)).

  3. \(\varepsilon_{\max}\) — the KAM threshold. Compute \(\delta / (2(N-1))\). Every new constraint must satisfy \(\|\Delta P\|_\infty < \varepsilon_{\max}\).

A 10-line script to get started:

import numpy as np

def autonomy_certificate(P: np.ndarray) -> dict:
    N = P.shape[0]
    evals = np.linalg.eigvals(P.T)
    delta = 1.0 - np.max(np.abs(evals[1:]))
    t_mix = N / delta * np.log(N)
    eps_max = delta / (2 * (N - 1))
    return {"N": N, "delta": round(delta, 6),
            "t_mix_ticks": int(t_mix),
            "eps_max": round(eps_max, 8)}

Run this in your CI pipeline on every harness-config change. If \(\delta\) drops below your threshold, the build fails with a message identifying the invariant subset (via a simple graph-reachability check on the transition digraph). No ambiguity. No “it worked in my local test.” Just a number that went below a line.

Discussion

The ergodicity framework has limitations, and it’s worth stating them plainly. First, it’s a necessary but not sufficient condition for autonomy: an ergodic harness can still produce poor code if the LLM’s per-step quality is low. Ergodicity guarantees exploration, not exploitation. Those are different things, and this framework only handles the former.

Second, the finite-state assumption is an idealization. A production harness with a continuous context window is not literally finite-state, but the coarse-graining results in Coarse-Graining Autonomy justify the discretization to within a computable error. Good enough for engineering purposes.

Third, the KAM certificate is a local result. It certifies that a small perturbation preserves ergodicity, but it does not tell you what happens at a large perturbation (say, replacing the entire tool layer). For that, the percolation analysis in Percolation of Autonomy is the right tool.

But the deeper methodological point—and this is what I find genuinely exciting—is that autonomy, far from being some philosophical or behavioral property, is a structural one. It’s a property of the transition matrix, not of the LLM weights. That reframing is what makes it CI-auditable, what makes it amenable to perturbation analysis, and what makes the entire series of posts—spectral, percolative, cohomological, geometric—cohere into a single design calculus. You can put a number on it. You can test it in a pipeline. And that changes everything about how you reason about agent reliability.
